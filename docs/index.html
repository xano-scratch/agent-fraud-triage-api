Agent Fraud-Triage API

One governed Xano API a fraud team's analysts and their AI agents both call, where the same authority rules decide every action and one audit trail records every attempt, allowed or refused.

What it proves

A fraud analyst and the analyst's AI agent hit the same permissioned, logged endpoints. Clearing and escalating an alert is in scope for both. Freezing an account is senior-only, so an analyst (and the analyst's agent) is refused at the API layer with the deciding rule, and the refusal is written to the audit trail just like an allowed action. The rule that matters lives once, in one function both the person and the agent run through.

Try it in a minute

  1. Open the app and click Continue as Avery (analyst).
  2. On the Triage board, drag a high-severity alert from Open to Escalated. It moves at once and a line appears in the Audit trail.
  3. Open an account and try Freeze. You are refused, and the refused attempt is on the Audit trail with the deciding rule.
  4. In a second window, continue as Sloan (senior) and freeze the same account. Avery's screens update live, no reload.
  5. Open Agents, create a key, and ask your agent to triage the open queue. It drafts actions for you to approve.

Use this template

git clone https://github.com/xano-scratch/agent-fraud-triage-api
cd agent-fraud-triage-api
npm install
npm run xano:deploy    # deploys and seeds the backend on the Xano Engine, no account
npm run dev            # opens the app, pointed at it

For a cloud link that works with ChatGPT and Claude: npx xanosdk login once, then npm run xano:deploy:ephemeral.
